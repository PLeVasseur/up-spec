== Overview

The Communication Layer APIs provide the common language specific interfaces for the pub/sub, notification, and RPC patterns supported by uProtocol implementations. The interfaces are declared in the xref:../languages.adoc[language-specific uProtocol libraries] and as such are merely described at a high level in this document to allow the language-specific libraries to declare the interface signatures using appropriate programming language constructs.

== Interfaces

.Communication Layer Interfaces
[#messaging-apis, cols="1,1,3"]
|===
|Messaging Pattern | Interface Name | Purpose

| Pub/Sub
| `*Subscriber*`
a| Provide `subscribe()` and `unsubscribe()` functionality to published topics, as well as setup listeners to receive the published messages.

* *MUST* be able to handle persistent subscriptions such that the subscriber can remain subscribed even when the subscribe is terminated. 


| Pub/Sub
| `*Publisher*`
| Provide `publish()` API so publishers can send a message to a given topic.

| Notification
| `*Notifier*`
a| Send notification to a specific destination. 

* *MUST* provide `notify()` API that passes the notification topic, the destination address (who to send the notification to), any optional payload, and any other message metadata.

| Notification
| `*NotificationListener*`
a| Register & unregister notification Listeners.

| RPC
| `*RpcServer*`
| Server-side RPC API that a service uses to register callbacks (or other mechanisms) that will process incoming requests and then automatically generate uProtocol response messages.

| RPC
| `*RpcClient*`
| Client-side RPC API to invoke service methods and handle the responses from the service.

|===

[.specitem,oft-sid="dsn~communication-layer-impl-async~1",oft-needs="impl,utest",oft-tags="CommunicationLayerImpl"]
--
Implementations of the <<messaging-apis>> *MUST* be non-blocking and *SHOULD* be asynchronous.
--

[.specitem,oft-sid="dsn~communication-layer-impl-error-handling~1",oft-needs="impl,utest",oft-tags="CommunicationLayerImpl"]
--
Implementations of the <<messaging-apis>> *MUST* adhere to the xref:../basics/error_model.adoc[uProtocol Error Model] for error handling for the respective APIs.
--

Implementations of the <<messaging-apis>> *MAY* use _Exceptions_ or other language-specific error handling mechanisms to indicate an erroneous outcome of a method invocation.

[.specitem,oft-sid="dsn~communication-layer-api-declaration~1",oft-needs="impl",oft-tags="LanguageLibrary"]
--
Each xref:../languages.adoc[language-specific uProtocol library (Language Library)] *MUST* declare the <<messaging-apis>> using corresponding programming language specific means.
--

[.specitem,oft-sid="dsn~communication-layer-api-namespace~1",oft-needs="impl",oft-tags="LanguageLibrary"]
--
Each Language Library *MUST* package (group) the <<messaging-apis>> into a folder (package/namespace) called `communication`.
--

[.specitem,oft-sid="dsn~communication-layer-impl-default~1",oft-needs="impl,utest",oft-tags="LanguageLibrary"]
--
Each Language Library *MUST* provide a _default_ implementation of the <<messaging-apis>> based on the (abstract) xref:../up-l1/utransport.adoc[Transport Level API].
--

NOTE: Additional information regarding implementation can be found in the respective language-specific uProtocol library documentation.

[[req-ssr-peer-rpc-ends]]
=== RPC calls always end

[.specitem,oft-sid="req~ssr-peer-rpc-ends~4",oft-title="RPC calls always end",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
*The deadline.*
The element *MUST* give every RPC call a deadline: the TTL of its request, counted from when the request was created.
An RPC request's TTL is greater than 0 (xref:../basics/uattributes.adoc[UAttributes], `+dsn~up-attributes-request-ttl~1+`), and what the element does with a request whose TTL is 0 is stated in xref:../up-l1/route-observation.adoc#req-ssr-qos-ttl[Expired messages are not processed] and, for its answer at a server, in <<req-ssr-peer-rpc-undecodable-answered,An undecodable request is answered>>.
So a call whose server has vanished or never answers completes with an error by its TTL.
A response completes the call only where the element accepts it before that TTL has passed (xref:../up-l1/runtime.adoc#req-ssr-bound-wait[Every bounded wait has a logical deadline]).

*A failure that is reported to the element.*
Where a call's failure is reported to the client's element, by the binding's count of the request's receivers (<<req-ssr-peer-rpc-no-server,A call with no server fails at once>>), by a server's `+InvalidArgument+` answer (<<req-ssr-peer-rpc-undecodable-answered,An undecodable request is answered>>) or by the Streamer's error response (xref:streamer.adoc#req-ssr-streamer-rpc-error-response[An RPC request that cannot be dispatched is answered, best effort]), the element *MUST* set the call's outcome as soon as it has that report, for an answer as soon as its wire accepts it (<<req-ssr-rpc-check-at-arrival,A response completes its call only once its wire accepts it>>), without waiting out the TTL.

*Completion.*
The element *MUST* end a call's tenure at its completion, by an accepted response, by its TTL, by its cancellation, by a peer's failure or at once for want of a server (<<req-ssr-peer-rpc-no-server,A call with no server fails at once>>), so that no later response completes it.
The element *MUST NOT* make the completion wait for the release of what the call owned.

*The slot's return.*
The element *MUST* return the call's slot to the table once the slot holds nothing whose release is pending or in progress, and not before:

* A decoded response or a retained owner that the call held is released as xref:../up-l1/runtime.adoc#req-ssr-heap-slot-types[A decoded value is destroyed once, as its route's class admits] and xref:../up-l1/runtime.adoc#req-ssr-release-lease-drop[A lease gives back its slot and nothing else] state.
* Until that release completes, the storage that holds it stays charged and is not reused, whether it stays with the call's slot or has passed to a release service.
* The route's admitted capacity covers it in either place.
--

* *fault-injection*: a server killed during a call.

*Rationale.*
A vanished server cannot release its client resources, so the client needs its own expiration path and a reusable call slot.
Waiting out the TTL of a call whose failure is already known would only delay the error.

The TTL is a logical deadline (xref:../up-l1/runtime.adoc#req-ssr-bound-wait[Every bounded wait has a logical deadline]).
A TTL of 0 means that a message never expires (xref:../basics/uattributes.adoc[UAttributes], `+dsn~up-attributes-ttl~1+`), so a call needs a positive one to end.

_The slot's return._
Giving the slot back when the call ends, while the call still holds a decoded owned response or a retained owner whose return is pending, would reuse storage that is still owned.

[[req-ssr-peer-rpc-correlation]]
=== A response reaches only its own call

[.specitem,oft-sid="req~ssr-peer-rpc-correlation~4",oft-title="A response reaches only its own call",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
*Delivery.*
The element *MUST* deliver a response only to the call that sent its request.
The element *MUST* refuse and count a response that arrives after its call has ended, including one that arrives at a slot a later call now uses.

*Tied to the slot's tenure.*
The element *MUST* tie the following to the slot's current tenure, atomically with claiming the slot for the response:

* the response's full request ID;
* for a call tied to a peer, that peer's full identity and incarnation.

It *MUST* do so in one of two ways:

* it compares them in the same exclusive step that claims the slot; or
* where its mechanism claims first, it compares them again after the claim.

*A mismatch.*
In either way, the element *MUST* complete nothing and record nothing in the call for a response that does not match, and *MUST* give back a slot that it claimed for it.
Either way no reuse, wrap or delay lets a response complete another call, on every route.

*Order.*
The element *MUST* make that tie before any wire check, so on an E2E route the echo never sees such a response.

*E2E routes.*
On an RPC route with the E2E wire, the wire also checks that a response answers its call exactly (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-rpc-echo[An E2E response answers exactly its call]), and the element completes the call only once the wire accepts the response (<<req-ssr-rpc-check-at-arrival,A response completes its call only once its wire accepts it>>).

*Dependency.*
It relies on request IDs being unique within the window (xref:../basics/uuid.adoc#req-ssr-ids-unique[Message IDs are unique]).
--

* *test*
** A response after expiry, at a reused slot: refused and counted, and never delivered to the later call.

*Rationale.*
A reused slot can carry a later call.
Tying the response's full request identity to the slot's current tenure as the slot is claimed prevents a delayed response from completing that later call.

The width at which a representation keeps the request ID and the peer tied to the call is stated in xref:../basics/platform.adoc#req-ssr-atomic-windows[Every narrowed value states its window].

[[req-ssr-rpc-check-at-arrival]]
=== A response completes its call only once its wire accepts it

[.specitem,oft-sid="req~ssr-rpc-check-at-arrival~4",oft-title="A response completes its call only once its wire accepts it",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
*First, the tie to the call.*
When a response that the preceding binding envelope checks, element metadata admission (including its filters) and peer classification (xref:../up-l1/peers.adoc#req-ssr-peer-stale-rejected[Stale peers are rejected]; xref:../up-l1/peers.adoc#req-ssr-peer-admission[Undeclared peers cannot lock out declared ones]) have admitted arrives at call arrival processing, the element *MUST* first tie it to the call's current tenure as <<req-ssr-peer-rpc-correlation,A response reaches only its own call>> requires, which also states what becomes of a response that does not match.
A response refused by an earlier envelope, metadata or peer check, or by a failed current-tenure tie, records nothing in any call and gets none of the checks below.

*Then, on an E2E route where it applies, pre-substitution declared-sender membership.*
After the tie to the call's current tenure succeeds and before checking the response's TTL, the element *MUST* apply the pre-substitution declared-sender membership check of xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-data-id[One data ID per sender and route], "Pre-substitution declared-sender membership", on a response route that selects the E2E wire wherever that check applies, using the matched call's actual method under the same tenure protection and arrival serialization.
Where that check fails, the response is a refused response: nothing completes, no later TTL, encoding, unprotected, native-preflight or E2E payload check is made for it, no expected data ID is derived, no E2E receiving state or figures are allocated or mutated, and the element *MUST* record that refusal's undeclared-source cause as that call's last refusal (distinct from E2E receiving state; an RPC client still keeps no E2E receiving slot), give back any arrival claim under the call's arrival-claim mechanism without writing any later tenure, immediately hand off the refused frame's whole owner under the route's and binding's pre-reserved return contract (xref:../up-l1/runtime.adoc#req-ssr-release-lease-drop[A lease gives back its slot and nothing else]; xref:../up-l1/bindings/lifecycle.adoc#req-ssr-binding-frame-drop[What a received frame's destructor may do]), keeping it charged until actual return completes, and keep the call open for another copy subject to cancellation, peer failure and logical TTL.
That refusal's one route count is the undeclared-source count that xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-data-id[One data ID per sender and route] states, and is not repeated here.
An earlier failed peer check or failed tenure tie records nothing in any call.

*Then, the TTL and the admission.*
After the tie to the call succeeds and any applicable pre-substitution declared-sender membership check above passes, the element *MUST* check the response's TTL as xref:../up-l1/route-observation.adoc#req-ssr-qos-ttl[Expired messages are not processed] states, and then apply xref:../up-l1/payload-paths.adoc#req-ssr-wire-encoding-checked[A wire is given only a payload of its own encoding] before it gives the response to a wire.
A response that one of these checks refuses is a refused response: no later check is made for it, and no wire reads it.

*Then, on the native protection composition, its checks.*
On a response route that selects the native protection composition, the element *MUST* then make the checks of xref:../up-l1/integrity.adoc#req-ssr-integrity-checked-at-admission[In-place frames are checked once, at admission], "On a route that selects the native protection composition", before it gives the response to the E2E wire: for every response, stable, legal access to its outer extent, and that extent against the route's admitted set, E or H; and, on the value branch, the writer's layout identity and ABI and the inner value's address.
A response that one of them refuses is a refused response: nothing completes, the call stays open for another copy, and the element *MUST* count the refusal once, under the native shape or agreement cause, in the route's counter, not in the E2E counter and not as `+unprotected+`, and record it as the call's last refusal.

*Then, the wire check.*
Otherwise the element *MUST* run the route's wire check on the bytes the call keeps, before the call completes.

* The element *MUST* complete nothing with a refused response, and *MUST* keep the call open for another copy.
* The element *MUST* count each refused response once on its route, under the cause of the check that refused it.
It *MUST NOT* count again a refusal that the pre-substitution declared-sender membership check, the TTL check, the admission or the checks of the native protection composition above counted, and on a response route that selects the E2E wire the one count of a refusal by that wire, or of a response with no E2E header, is the count that xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-counted[End-to-end refusals are named, and counted once] states.
* The element *MUST* end at its TTL a call that is still pending then, naming, where the call got an advisory refusal answer, the kind that xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-answered[A refused request is answered, final or advisory] has it name (which retains precedence over any subsequent ordinary refusal, including a pre-substitution declared-sender membership refusal), and otherwise the last refusal that it recorded (a pre-substitution declared-sender membership refusal included).

*After the wire accepts, on the native protection composition.*
On a response route that selects the native protection composition, the element *MUST* act on the shape that the E2E wire's verdict names (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-rpc-echo[An E2E response answers exactly its call], "Shapes of a protected native response"):

* a Value completes the call with a view of its value, formed only where the value-branch checks passed for that response;
* a Failed response completes the call with its commstatus, and no payload is decoded;
* a final Control rejects the call with `+Aborted+`, naming the kind, and an advisory Control leaves it open (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-answered[A refused request is answered, final or advisory]).

A Value verdict for a response on which the value-branch checks did not run forms no view: the element *MUST* refuse that response under the native shape cause, once, and keep the call open.

*A failed response, and a response with no payload.*

* A tied response whose commstatus is not `+Ok+` reports its call's failure (xref:../basics/error_model.adoc[uProtocol Error Model (UStatus)], `+dsn~service-error-model-failed-rpc~1+`).
On a route that does not select the E2E wire, the route's wire check of such a response is the check of its commstatus, and the element *MUST* complete the call with that commstatus once the response's TTL check has admitted it.
For such a response, this item replaces the refusal, the result and the count that xref:../up-l1/payload-paths.adoc#req-ssr-wire-encoding-checked[A wire is given only a payload of its own encoding] states for an encoding identifier that no wire declares and for a missing payload: a payload that the response carries reaches only a wire that declares its encoding identifier, and the call completes with that commstatus whether or not that wire decodes it.
On a route that selects the E2E wire, its wire check is the E2E wire's, as for any response.
* On a route that does not select the E2E wire, a tied response whose commstatus is `+Ok+` and that has no payload, to an operation whose declared contract permits that absence, gives a wire no bytes: once its TTL check has admitted it, the element *MUST* complete the call with the absence, reported as xref:../up-l1/payload-paths.adoc#req-ssr-wire-encoding-checked[A wire is given only a payload of its own encoding] states.
On a route that selects the E2E wire, a response with no payload has no E2E header, and is refused as xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-counted[End-to-end refusals are named, and counted once] states, whatever its operation permits.

*Refusal answers.*
The element *MUST* check a refusal answer like any response: after earlier envelope, metadata and existing peer admission, it ties the answer to its call and makes the checks above, including any applicable pre-substitution declared-sender membership check, its TTL check, its admission, any protected-native preflight and the route's wire check, before the answer has any effect.
What the element then does with a final answer and with an advisory one is stated in xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-answered[A refused request is answered, final or advisory].

*The call's tag.*
The element *MUST* record the call's tag before its request is sent, and refuse a response that arrives before then.

*Concurrency.*

* The element *MUST* run the arrival checks of one response route one at a time, so a copy is never refused because another copy of the same response is being checked.
On a response route that a binding serves by push, the binding delivers one response at a time (xref:../up-l1/bindings/interface.adoc#req-ssr-binding-response-delivery[A binding delivers one response route from one thread at a time]), which relaxes none of the element's checks.
* Where a peer failure finds a call's response being checked, the element *MUST* fail the call at once if that response is refused.
--

Completing a call before checking its wire would let a corrupt first copy exclude a later intact response.

Refusal answers come only from a wire that protects calls (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-answered[A refused request is answered, final or advisory]).

On the native protection composition, every native check of a response comes before the wire, and a client keeps no receiving slot, so nothing is committed before a native refusal; the one refusal after the wire's acceptance, of a Value verdict for which the value-branch checks did not run, follows no change of state either.

A call that ends at its TTL ends logically (xref:../up-l1/runtime.adoc#req-ssr-bound-wait[Every bounded wait has a logical deadline]).

Giving a claim back returns the call to waiting for another copy.
What the refused copy owns is released as xref:../up-l1/runtime.adoc#req-ssr-heap-slot-types[A decoded value is destroyed once, as its route's class admits] states, and storage that an unfinished release still holds is not reused (xref:../up-l1/runtime.adoc#req-ssr-release-lease-drop[A lease gives back its slot and nothing else]).

[[req-ssr-peer-rpc-undecodable-answered]]
=== An undecodable request is answered

[.specitem,oft-sid="req~ssr-peer-rpc-undecodable-answered~8",oft-title="An undecodable request is answered",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
*The answer.*
Where the element's RPC server role receives a request whose header the element can parse, the element *MUST* answer the request once, as a response to its reply address, with commstatus `+InvalidArgument+`, producing the answer without heap, where the check of "The order of the checks" that refuses the request refuses it for one of these causes:

* a TTL of 0, on a route that does not select the E2E wire (xref:../up-l1/route-observation.adoc#req-ssr-qos-ttl[Expired messages are not processed], which states the refusal of such a request and its count);
* an encoding identifier that no wire of the route declares, or a missing payload where the request's operation requires a value, on a route that does not select the E2E wire (xref:../up-l1/payload-paths.adoc#req-ssr-wire-encoding-checked[A wire is given only a payload of its own encoding]);
* a payload that the fourth check cannot decode, for a reason other than an end-to-end check.

*The order of the checks.*
When a request whose header the element can parse reaches the route of its RPC server role, the element *MUST* make these checks of it in this order, and *MUST NOT* make a later one of them for a request that an earlier one refuses:

. its TTL: a TTL of 0, its expiry, and a clock that cannot be read (xref:../up-l1/route-observation.adoc#req-ssr-qos-ttl[Expired messages are not processed], which also states that a request that it refuses gets no check of its payload and no other count);
. its payload, before any wire: on a route that does not select the E2E wire, its encoding and its presence (xref:../up-l1/payload-paths.adoc#req-ssr-wire-encoding-checked[A wire is given only a payload of its own encoding]); on a route that selects it, whether it carries an E2E header (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-counted[End-to-end refusals are named, and counted once]), and then, on a route that selects the native protection composition, the element's protected-native preflight: stable, legal access to the request's outer extent, that extent against the one extent that the route admits for a request, E, and, because a request always takes the value branch, the writer's layout identity and ABI and the actual address of the inner value (xref:../up-l1/integrity.adoc#req-ssr-integrity-checked-at-admission[In-place frames are checked once, at admission]; xref:../up-l1/wires/native.adoc#req-ssr-native-agreement[A native type is read only under its exactly agreed layout]);
. on a route that selects the E2E wire, that wire's check (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-answered[A refused request is answered, final or advisory]);
. the decode of its payload, where it has one, with, on a native route that does not select the E2E wire, the check of its agreed layout (xref:../up-l1/wires/native.adoc#req-ssr-native-agreement[A native type is read only under its exactly agreed layout]); on a route that selects the native protection composition, this check makes no native check of its own: the view of the request's value rests on the protected-native preflight that the second check made for that request, and no native refusal follows the E2E wire's check.

A request with no payload whose operation's declared contract permits that absence passes the second check on a route that does not select the E2E wire, and no wire decodes anything for it.

The element *MUST* make these checks only for a request that the checks which other items state for it have admitted, which come first, in this order: its binding's physical checks of its envelope and the element's admission of its metadata—following xref:../up-l1/bindings/storage.adoc#req-ssr-binding-metadata-admission[Where a lending binding's profile invokes shared metadata hand-over, the element admits metadata once in fixed order] where the binding's profile invokes that shared procedure, and otherwise the route's applicable physical and metadata admission; the classification of its peer (xref:../up-l1/peers.adoc#req-ssr-peer-stale-rejected[Stale peers are rejected]; xref:../up-l1/peers.adoc#req-ssr-peer-admission[Undeclared peers cannot lock out declared ones]); and, on a route that selects the E2E wire wherever that check applies (an empty received source or an empty configured method fixed sink), the pre-substitution declared-sender membership check (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-data-id[One data ID per sender and route], "Pre-substitution declared-sender membership").
The element *MUST NOT* make one of those after an earlier one has refused the request.
A request that one of them refuses gets none of these checks, no expected data ID, no E2E payload check and no answer under this item (no wire refusal answer and no `+InvalidArgument+` answer), and its refusal is returned or counted once as the item of that check states (for pre-substitution declared-sender membership, once under the undeclared-source cause and under no later cause).

*The one count.*
The element *MUST* count each request that one of these checks refuses exactly once on its route, under the cause that the refusing check names, also where a typed operation returns that refusal's result to its caller: a refusal by the first check as xref:../up-l1/route-observation.adoc#req-ssr-qos-ttl[Expired messages are not processed] states, a request with no E2E header as xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-counted[End-to-end refusals are named, and counted once] states, a refusal by the protected-native preflight under the cause of the native check that refuses it (xref:../up-l1/integrity.adoc#req-ssr-integrity-checked-at-admission[In-place frames are checked once, at admission]; xref:../up-l1/wires/native.adoc#req-ssr-native-agreement[A native type is read only under its exactly agreed layout]) and not in the E2E counter, and a refusal by the E2E wire as xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-answered[A refused request is answered, final or advisory] states.
The element *MUST NOT* count again under any cause of these four checks a request that a prerequisite check above refused, including a pre-substitution declared-sender membership refusal (whose one route count is the undeclared-source count of xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-data-id[One data ID per sender and route]).
Each received copy of a request is a request of its own here, and an answer to a request is no second count of it.

*No second answer.*
Where a typed operation returns to its caller the result of a refusal of a request, by one of these checks or by a check that comes before them, the element *MUST NOT* give that caller a means to answer the request, whether or not the element answers it.

*Sending the answer.*
Before handing off the refused request frame's owner, the element *MUST* preserve in fixed reserved state only the reply address, message identity and request tag (where a wire read one) needed for any required answer, and *MUST* hand off that refused request frame's whole owner immediately as the clause "Release" states before sending the answer; the element *MUST* then send any required answer as any response on that route is sent, under the route's overflow policy and heap class, including a bounded wait where the route declares one, so that a full response route or bounded answer wait never retains the refused request frame's owner on the caller path.

*Requests that get no answer.*

* A request whose header cannot be parsed has no reply address: the element *MUST NOT* answer it.
Its refusal is as xref:../basics/error_model.adoc#req-ssr-refuse-no-panic[No panic on runtime paths] states for a malformed frame.
Where the element refuses it, the element *MUST* count it exactly once on its route, also where a typed operation returns that refusal's result to its caller.
Where the request's binding refuses it in a check of its own, its refusal is returned or counted once as that binding's item states.
* The element *MUST NOT* answer a request that the first check refuses for its expiry or because the clock cannot be read, on any route.
* On a route that selects the E2E wire, the element *MUST NOT* answer a request that it refuses before the E2E wire reads it, by pre-substitution declared-sender membership (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-data-id[One data ID per sender and route], "Pre-substitution declared-sender membership") or by the first or the second check, the protected-native preflight included: among them a request failing pre-substitution declared-sender membership, one whose TTL is 0, one with no payload, one whose payload is of an encoding other than the E2E wire's, and one that the protected-native preflight refuses.
The E2E wire has not read such a request, so the request has no tag for an answer to echo (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-rpc-echo[An E2E response answers exactly its call]).
* The element *MUST* count once an `+InvalidArgument+` answer of this item that it cannot send, as an event of its own and not as a second count of its request; where the route's overflow policy discards the answer, that count is the discard's (xref:../up-l1/runtime.adoc#req-ssr-qos-overflow[Overflow acts as declared]).
* In each of these cases the client's call gets no answer to that request.
A call whose request's TTL is greater than 0 then ends as <<req-ssr-peer-rpc-ends,RPC calls always end>> states: at its TTL, where it is still pending then.
A request whose TTL is 0 is invalid, and the element refuses it at a client before it is sent (xref:../up-l1/route-observation.adoc#req-ssr-qos-ttl[Expired messages are not processed]); for a peer that sends one, this item states no completion of its call.

*End-to-end refusals.*
Which answer the element gives a request that the E2E wire refuses is stated in xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-answered[A refused request is answered, final or advisory]: none to a request that the wire finds corrupt, whatever data ID it names; `+InvalidArgument+` to one that is not corrupt and whose data ID was not declared; none to one that the wire refuses as an identity mismatch, whose data ID was declared and differs from the request's expected data ID; and the wire's refusal answer, final or advisory, to every other.
Such a request gets only that answer, and is counted as xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-counted[End-to-end refusals are named, and counted once] states.

* The element *MUST* produce and send the `+InvalidArgument+` answer to a request that the E2E wire finds not corrupt and refuses for a data ID that was not declared as it does the answer to an undecodable one, as "The answer" and "Sending the answer" state.
* The element *MUST* answer as an undecodable one a request that passes the E2E wire's check and then fails the inner wire's decode.

*Tags.*
The element *MUST* hand every answer, its own and the application's, to the route's wire with its request's tag, where a wire of the route read one, so that on an E2E route the answer echoes that request (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-rpc-echo[An E2E response answers exactly its call]).

*Release.*
Immediately after deciding and counting the refusal (preserving only the reply address, message identity and request tag needed for any required answer in fixed reserved state), and before sending any required answer, the element *MUST* hand off every refused request frame's whole owner once, without allocating, panicking or waiting, into the route's and binding's pre-reserved return path (xref:../up-l1/runtime.adoc#req-ssr-release-lease-drop[A lease gives back its slot and nothing else]; xref:../up-l1/bindings/lifecycle.adoc#req-ssr-binding-frame-drop[What a received frame's destructor may do]), keeping the owner charged until actual return completes.
Answer transmission is not a prerequisite for handing off the refused request frame's owner.

*Rationale.*
A known decoding failure can be reported immediately.

_The order of the checks._
The TTL check reads only the header, so an invalid or expired request is refused before its payload is looked at (xref:../up-l1/route-observation.adoc#req-ssr-qos-ttl[Expired messages are not processed]); the payload is admitted before any wire reads it, and the E2E wire runs before the decode.
On a route that selects the native protection composition, the native checks that a view would need come before the E2E wire, so that no native refusal follows a change of the wire's state.
So the one check that refuses a request names the cause of its one count, and decides its answer.

_End-to-end refusals._
The server cannot tell a corrupted or duplicated copy from the only one, and an answer that ends a call could end a call that it is still serving.
So a request that the end-to-end check refuses gets no answer that could end such a call: a corrupt request gets none, and a final refusal answer is given only where the wire establishes that this server instance never delivered the request and never will.
The one other exception is the `+InvalidArgument+` answer to a request that is not corrupt and whose data ID was not declared.
A request refused as an identity mismatch gets no answer: its reply address comes from metadata that its protected data ID contradicts, so no answer to it could reach a client that would accept it.
An advisory answer leaves the call open for its real response (xref:../up-l1/wires/e2e.adoc#req-ssr-e2e-refusal-answered[A refused request is answered, final or advisory]).

_Requests refused before the E2E wire._
On a route that selects the E2E wire, an answer echoes its request's tag, which only the E2E wire reads.
A request refused before that wire reads it has none, so an answer to it could not meet the client's E2E check; a client's call whose request's TTL is greater than 0 ends at that TTL, where it is still pending then.

_Expired requests._
The call of an expired request has ended at its client, and a server whose clock cannot be read cannot tell whether it has: an `+InvalidArgument+` answer would report the server's fault as the client's.

_Heap use of the answer._
A serialized route whose binding allocates storage for every frame it sends needs heap to send an answer.

[[req-ssr-peer-rpc-no-server]]
=== A call with no server fails at once

[.specitem,oft-sid="req~ssr-peer-rpc-no-server~2",oft-title="A call with no server fails at once",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
*With an exact receiver count.*
On a binding that declares an exact receiver count (xref:../up-l1/bindings/interface.adoc#req-ssr-binding-receiver-count[A binding that declares an exact receiver count reports it for each request]), the element *MUST* fail at once a call whose request that binding's report shows to have reached no server, with an error that names the cause, instead of waiting out the call's TTL.

*What is not such a report.*
A count of notification listeners, a discovery result and a count taken at another time are not that report, and the element *MUST NOT* fail a call at once on any of them.

*Without it.*
On any other binding, the element *MUST NOT* fail a call at once for want of a server.
A call that is still pending when its TTL passes ends at that TTL, as <<req-ssr-peer-rpc-ends,RPC calls always end>> states.

*A later response.*
A call that failed at once has ended, and a response that arrives for it later is refused as <<req-ssr-peer-rpc-correlation,A response reaches only its own call>> states.
--
