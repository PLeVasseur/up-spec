== Overview

https://iceoryx.io[Eclipse iceoryx2&trade;] is an efficient, and ultra-low latency inter-process communication middleware. The library is designed to provide you with fast and reliable zero-copy and lock-free inter-process communication mechanisms.

This document defines how uProtocol messages can be exchanged by means of iceoryx2 _Services_.

== iceoryx2 Version

[.specitem,oft-sid="dsn~up-transport-iceoryx2-protocol-version~1",oft-needs="impl",oft-tags="TransportLayerImpl"]
--
Each transport implementing this specification **MUST** use version `0.7.0` of the iceoryx2 protocol in order to ensure interoperability of different language libraries.
--

== iceoryx2 MessagingPattern

[.specitem,oft-sid="dsn~up-transport-iceoryx2-messaging-pattern~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
All types of uProtocol messages *MUST* be transferred using iceoryx2's PublishSubscribe MessagingPattern only. iceoryx2's RequestResponse API *MUST NOT* be used.
--

== Frame Mapping

A native uProtocol frame consists of _UAttributes_, optional payload wire-format metadata, and optional payload bytes. The following sections define how these are mapped to/from iceoryx2 Services without requiring a generated Protocol Buffers envelope.

=== UAttributes

[.specitem,oft-sid="dsn~up-transport-iceoryx2-attributes-mapping~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
The value of a iceoryx2 Service that is used to convey a uProtocol frame *MUST* have a https://docs.rs/iceoryx2/0.6.1/iceoryx2/service/builder/publish_subscribe/struct.Builder.html#method.user_header[user header] as defined in <<uAttributes Mapping to iceoryx2 user header>>.
--

==== uAttributes Mapping to iceoryx2 user header

[source,rust]
----
#[repr(C)]
#[derive(ZeroCopySend)]
struct UProtocolHeader {
    uprotocol_major_version: u8,
    id_msb: u64,
    id_lsb: u64,
    message_type: u8,
    priority: u8,
    ttl_present: u8,
    ttl: u32,
    request_id_present: u8,
    request_id_msb: u64,
    request_id_lsb: u64,
    permission_level_present: u8,
    permission_level: u32,
    commstatus_present: u8,
    commstatus: u8,
    source_ue_id: u32,
    source_ue_version_major: u32,
    source_resource_id: u32,
    sink_present: u8,
    sink_ue_id: u32,
    sink_ue_version_major: u32,
    sink_resource_id: u32,
    metadata_len: u64,
    payload_len: u64,
    payload_alignment: u64,
}
----

.uAttributes Mapping to UProtocolHeader, iceoryx2 User Header
[%autowidth]
|===
| field | value

| `uprotocol_major_version`
a| *MUST* be set to a single byte representing the uProtocol major version (`0x01` at the time of writing)

| `id_msb`, `id_lsb`, `message_type`, `priority`, `ttl_present`, `ttl`
a| *MUST* be set from the corresponding native `UAttributes` fields.

| `request_id_present`, `request_id_msb`, `request_id_lsb`
a| *MUST* preserve the native `UAttributes.request_id` field when present. When absent, `request_id_present` *MUST* be zero and the request-id value fields *MUST* be ignored.

| `permission_level_present`, `permission_level`
a| *MUST* preserve the native `UAttributes.permission_level` field when present. When absent, `permission_level_present` *MUST* be zero and `permission_level` *MUST* be ignored.

| `commstatus_present`, `commstatus`
a| *MUST* preserve the native `UAttributes.commstatus` field when present. The status value *MUST* use the language binding's stable native uProtocol status-code mapping.

| `source_*`
a| *MUST* be set from the numeric native source `UUri` fields. The variable-length source authority name *MUST* be preserved in the implementation metadata prefix.

| `sink_present`, `sink_*`
a| *MUST* indicate whether a sink exists. When present, the sink fields *MUST* be set from the numeric native sink `UUri` fields and the variable-length sink authority name *MUST* be preserved in the implementation metadata prefix. When absent, `sink_present` *MUST* be zero and sink fields *MUST* be ignored.

| `metadata_len`
a| *MUST* identify the number of implementation metadata sidecar bytes preceding the frame payload bytes in the loaned iceoryx2 sample payload.

| `payload_len`, `payload_alignment`
a| *MUST* describe the payload loan size and requested serializer alignment. `payload_len` equal to zero with absent encoding represents no payload; `payload_len` equal to zero with present encoding represents a present empty payload.

|===

The user header *MUST NOT* contain a serialized generated `UAttributes` blob. Transports SHOULD project native attributes into fields that are cheap for the transport to inspect. URI entity/version/resource components are numeric and SHOULD live in the user header. Authority names are variable-length strings and SHOULD live in the implementation metadata prefix instead of fixed-capacity user-header buffers.

Variable metadata that is not naturally fixed-size for iceoryx2 user headers, such as URI authority names, custom `PayloadEncoding` fields, `traceparent`, and `token`, SHOULD be encoded in an implementation metadata prefix rather than forcing arbitrary fixed user-header capacities. The prefix length is carried by `metadata_len`. The prefix is transport metadata and *MUST NOT* be exposed as part of the frame payload by the language transport API.

==== Implementation Metadata Prefix

The implementation metadata prefix preserves variable frame metadata while keeping the iceoryx2 user header small and cheap to inspect. The prefix is stored before the user payload bytes in the underlying iceoryx2 sample payload and is hidden by the uProtocol transport API.

The prefix *MUST* preserve:

* `PayloadEncoding`, when payload encoding is present;
* `UAttributes.source.authority_name`;
* `UAttributes.sink.authority_name`, when a sink is present;
* `UAttributes.traceparent`, when present;
* `UAttributes.token`, when present.

The prefix binary representation for cross-language interoperability is:

[source]
----
metadata_prefix =
  magic[4] = "UFM1"
  source_authority: string
  sink_authority: optional<string>
  encoding: optional<encoding>
  traceparent: optional<string>
  token: optional<string>

encoding =
  kind: uint8                  // 0 = standard, 1 = custom
  standard_payload_format: uint8
                               // present only when kind == 0; UPayloadFormat value
  custom_id: string            // present only when kind == 1
  custom_content_type: string  // present only when kind == 1

string =
  len: uint32 little-endian
  utf8_bytes[len]

optional<T> =
  present: uint8      // 0 = absent, 1 = present
  T                   // present only when present == 1
----

Implementations *MUST* reject metadata prefixes with an unknown magic value, malformed UTF-8, invalid optional markers, trailing bytes, lengths that exceed the sample payload, or non-empty payload bytes without encoding metadata. Regardless of representation, the transport API *MUST* reconstruct the same native frame metadata on receive.

=== Payload Mapping

[.specitem,oft-sid="dsn~up-transport-iceoryx2-payload-mapping~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
An iceoryx2 `Sample` that is used to convey a uProtocol frame *MUST* expose through the uProtocol transport API the frame payload bytes exactly as produced by the selected serializer. Those bytes are arbitrary serializer output; they are not required to be represented as a generated protocol envelope.

An implementation *MAY* reserve metadata prefix bytes before the frame payload bytes in the underlying iceoryx2 sample payload. If it does so, those bytes *MUST* be hidden from the binding's transmit payload view and receive payload view.

When payload bytes are present, payload encoding metadata *MUST* be present. When payload encoding metadata is absent, `payload_len` *MUST* be zero and the frame has no payload.
--

[.specitem,oft-sid="dsn~up-transport-iceoryx2-payload-zero-copy~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
The iceoryx2 sample storage and user header used to convey a uProtocol frame through a direct true-zero-copy path *MUST* be loan-backed and shared-memory compatible:

* is self contained, no heap, no pointers to external sources, no handles to external resources (files etc)
* has a uniform memory representation
* does not use pointers to manage their internal structure
* has a lifetime of the entire program duration
--

Direct true-zero-copy transmit requires that the payload is written or constructed directly in the iceoryx2 transmit loan before the loan is sent. Direct true-zero-copy receive requires that the application borrows from the iceoryx2 receive sample lease without allocation, coalescing, or copied fallback storage.

The application payload exposed by the uProtocol transport API is a byte range within that sample storage. It may contain bytes produced by any selected serializer. Implementations *MAY* insert alignment padding between hidden metadata and exposed payload bytes when required by the serializer alignment request, but padding *MUST NOT* be exposed as payload and *MUST* be accounted for in the sample layout.

For stable-container payloads, the exposed payload byte range *MUST* begin at an address satisfying the stable-container `align` parameter and *MUST* have exactly the stable-container `size` for the fixed-size variant. The receive lease lifetime *MUST* cover any typed borrow derived from the sample payload. Rust stable-container typed receive MUST use a loan-backed stable receive method such as `borrow_stable_payload<T>()`.

Rust binding note: the storage and user-header types used with iceoryx2 **MUST** implement link:https://docs.rs/iceoryx2/0.6.1/iceoryx2/prelude/trait.ZeroCopySend.html[`ZeroCopySend`].

That encapsulates the following additional properties in Rust:

* Rust `enum` and `struct` are marked  as `#[reprpass:[(C)]]`
* members don't implement `Drop` explicitly
* has a `'static` lifetime

== iceoryx2 Service Name Structure

Message producers publish messages to the iceory2 inter-process communication using _ServiceNames_. Other clients can then use the same _ServiceName_ to receive the messages that are being published.

The iceoryx2 _ServiceName_ that is used to transfer a uProtocol message is derived from the message's `source` and `sink` attributes.

[.specitem,oft-sid="dsn~up-transport-iceoryx2-service-name~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
The ServiceName for sending a _Publish_ UMessage **MUST** consist of the following segments:

`up/[source.authority]/[source.ue_type]/[source.ue_instance]/[source.ue_version]/[source.resource]`

The ServiceName for sending a _Notification_ or _RPC Response_ UMessage **MUST** consist of the following segments:

`up/[source.authority]/[source.ue_type]/[source.ue_instance]/[source.ue_version]/[source.resource]/[sink.authority]/[sink.ue_type]/[sink.ue_instance]/[sink.ue_version]/[sink.resource]`

The ServiceName for sending an _RPC Request_ UMessage **MUST** consist of the following segments:

`up/[sink.authority]/[sink.ue_type]/[sink.ue_instance]/[sink.ue_version]/[sink.resource]`

Please refer to <<UUri Encoding Rules>> for details regarding the encoding of the `source` and `sink` UUris into the key expression's segments.

--

== iceoryx2 Service Attributes And Discovery

An iceoryx2 service name is exact, but uProtocol listeners can contain wildcards. To support streamer-style wildcard subscriptions, implementations SHOULD attach service attributes describing the concrete uProtocol source URI to each created publish/subscribe service.

[.specitem,oft-sid="dsn~up-transport-iceoryx2-service-attributes~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
An iceoryx2 uProtocol service created for a publish source *SHOULD* define service attributes for the effective source authority, entity type, entity instance, major version, and resource identifier. A listener whose source filter contains wildcards *SHOULD* discover matching concrete services by listing iceoryx2 services and matching those attributes against the source filter.
--

[.specitem,oft-sid="dsn~up-transport-iceoryx2-listener-fanout~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
When multiple uProtocol listeners match the same iceoryx2 service, the transport implementation *SHOULD* create an independent iceoryx2 subscriber for each listener registration. A received sample lease is consumed by one subscriber, so a single subscriber *MUST NOT* be used as the only fanout source for multiple independent uProtocol listeners.
--

=== UUri Encoding Rules

The table below contains the rules for encoding a UUri's fields into an iceoryx2 ServiceName's segments.

[cols="2,2,6"]
|===
| ServiceName Segment
| UUri Field
| Encoding

|`authority`
|`authority_name`
a| The segment *MUST* contain the (UTF8) string representation of the 

1. name of the host/authority that the (local) uEntity is running on, if authority name is empty.
2. authority name, otherwise.

|`ue_type`
|`ue_id`
a| The segment *MUST* contain the (UTF8) string representation of the
upper-case link:https://www.rfc-editor.org/rfc/rfc4648#section-8[base16 encoding] of the uEntity type identifier with all leading `0` characters omitted.

|`ue_instance`
|`ue_id`
a| The segment *MUST* contain the (UTF8) string representation of the
upper-case link:https://www.rfc-editor.org/rfc/rfc4648#section-8[base16 encoding] of the uEntity instance identifier with all leading `0` characters omitted.

|`ue_version`
|`ue_version_major`
a| The segment *MUST* contain the (UTF8) string representation of the
upper-case link:https://www.rfc-editor.org/rfc/rfc4648#section-8[base16 encoding] of the uEntity major version with all leading `0` characters omitted.

|`resource`
|`resource_id`
a| The segment *MUST* contain the (UTF8) string representation of the
upper-case link:https://www.rfc-editor.org/rfc/rfc4648#section-8[base16 encoding] of the resource identifier with all leading `0` characters omitted.

|===

=== Examples

The examples below assume that the local entity's authority name is `device1`.

.Publishing an event on a topic
--
[cols="2,8"]
|===
|*Source URI*
|`up://10AB/3/80CD`

|*Sink URI*
|-

|*iceoryx2 ServiceName*
|`up/device1/10AB/0/3/80CD`
|===
--

.Sending a Notification to another uEntity
--
[cols="2,8"]
|===
|*Source URI*
|`up://device1/10AB/3/80CD`

|*Sink URI*
|`up://device1/300EF/4/0`

|*iceoryx2 ServiceName*
|`up/device1/10AB/0/3/80CD/device1/EF/3/4/0`
|===
--

.Sending an RPC Request to a service provider
--
[cols="2,8"]
|===
|*Source URI*
|`up://403AB/3/0`

|*Sink URI*
|`up://device1/CD/4/B`

|*iceoryx2 ServiceName*
|`up/device1/CD/0/4/B`
|===
--

.Sending an RPC Response to a service client
--
[cols="2,8"]
|===
|*Source URI*
|`up://device1/CD/4/B`

|*Sink URI*
|`up://device1/403AB/3/0`

|*iceoryx2 ServiceName*
|`up/device1/CD/0/4/B/device1/3AB/4/3/0`
|===
--

.Subscribe to a specific Publish topic
--
[cols="2,8"]
|===
|*Source Filter*
|`up://device1/10AB/3/80CD`

|*Sink Filter*
|-

|*iceoryx2 ServiceName*
|`up/device1/10AB/0/3/80CD`
|===
--

.Subscribe to all Request messages for a given invokable method pointed to this uEntity
--
[cols="2,8"]
|===
|*Source Filter*
|`up://*/FFFFFFFF/FF/FFFF`

|*Sink Filter*
|`up://device1/CD/4/B`

|*iceoryx2 ServiceName*
|`up/device1/CD/4/B`
|===
--

Note that subscribing to all Request messages pointed to this uEntity for a given invokable method
means that we **MUST** determine the source in order to send Response messages.

The source UUri **MUST** be determined by deserializing the `uatributes_serialized` in the UProtocolHeader
and then creating the appropriate fully-qualified ServiceName.
