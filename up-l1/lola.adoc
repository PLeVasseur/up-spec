== Overview

Eclipse S-CORE LoLa is a low-latency shared-memory communication binding exposed through the S-CORE communication repository. This document defines how uProtocol native frames can be exchanged by means of LoLa generic events.

== LoLa Binding Model

uProtocol frames are mapped to LoLa events using type-erased generic APIs. A transport implementation SHOULD use `GenericSkeleton`, `GenericSkeletonEvent`, `GenericProxy`, and `GenericProxyEvent` with `SampleAllocateePtr<void>` and `SamplePtr<void>` rather than requiring generated application data types for every uProtocol payload schema.

An implementation using S-CORE generic events MUST ensure that the producer writes to the same raw event slot storage that `GenericProxyEvent` exposes to consumers. The middleware loan object and slot ownership metadata may be distinct from the byte address exposed to serializers.

=== Raw Sample Safety Contract

A LoLa binding that exposes direct true-zero-copy access to raw generic-event sample bytes *MUST* base that access on either a supported S-CORE raw-sample API or a version-pinned S-CORE layout assumption. If it relies on S-CORE internals, the binding *MUST* document the exact S-CORE source revision or released version and cite the concrete source files and functions whose allocation, slot layout, and consumer sample-address behavior are assumed.

Before exposing raw sample storage to application serializers or receive borrowers, the native bridge *MUST* check all of the following:

* TX and RX data pointers are non-null for non-zero sample sizes;
* configured sample alignment is supported, non-zero, and a power of two;
* exposed data pointers satisfy the configured sample alignment;
* slot offset multiplication and derived pointer arithmetic cannot overflow or underflow;
* the exposed payload/sample range is contained inside the configured sample storage range and a single allocation;
* pool ownership prevents double release and use-after-free across reserve, send, drop, receive, and release paths.

Language bindings *MUST* repeat the checks that are visible at the language boundary before constructing slices or typed views, including null-pointer rejection, configured sample-size bounds, and alignment checks. If these criteria cannot be proven for the pinned S-CORE version, the binding *MUST NOT* claim sound direct true-zero-copy raw-sample access and *MUST* return an unsupported or failed-precondition error for those paths until a supported raw-sample API is available.

[.specitem,oft-sid="dsn~up-transport-lola-generic-events~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
A LoLa uProtocol transport *MUST* use a LoLa event sample as the storage unit for one uProtocol native frame. The uProtocol payload bytes *MUST* be exposed as bytes within that sample and *MUST NOT* require a generated service-specific payload type at the transport API boundary.
--

The receive side follows the same ownership shape as the S-CORE Rust binding: a provider/skeleton owns transmit allocation and send, while each consumer subscription owns its receive queue and `SamplePtr` lifetimes.

[.specitem,oft-sid="dsn~up-transport-lola-subscription-fanout~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
When multiple uProtocol listeners match the same LoLa event, the transport implementation *SHOULD* create an independent LoLa proxy subscription for each listener registration. A `SamplePtr<void>` lease is consumed by one subscriber, so local application listeners and streamer listeners *MUST NOT* be multiplexed through a single consumed receive sample unless the implementation explicitly copies for secondary listeners.
--

[.specitem,oft-sid="dsn~up-transport-lola-subscribe-before-send~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
A LoLa listener registration *SHOULD* establish its proxy subscription before publishers are expected to send matching events. Implementations MUST NOT rely on events sent before subscription establishment being delivered to that listener.
--

== Sample Layout

LoLa generic events are configured with fixed sample `size` and `alignment` through `DataTypeMetaInfo`.

The sample layout is:

[source]
----
lola_sample =
  frame_header
  metadata_prefix
  alignment_padding
  payload_bytes
  unused_tail
----

The `frame_header` and `metadata_prefix` preserve `UFrameMetadata`, including all required `UAttributes` fields and optional `PayloadEncoding`. The exposed uProtocol payload view begins at `payload_bytes` and has the exact serializer-produced payload length.

[.specitem,oft-sid="dsn~up-transport-lola-fixed-sample-size~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
If a frame's metadata, padding, and payload cannot fit into the configured LoLa event sample size, `loan_tx` *MUST* fail before handing a transmit loan to the serializer.
--

[.specitem,oft-sid="dsn~up-transport-lola-alignment~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
A LoLa transport implementation *MUST* honor the serializer alignment requested by the zero-copy transport API, or fail `loan_tx` with an invalid-argument error when the configured event sample alignment cannot satisfy the request.
--

For stable-container payloads, the exposed payload byte range *MUST* begin at an address satisfying the stable-container `align` parameter and *MUST* have exactly the stable-container `size` for the fixed-size variant. The LoLa sample lease lifetime *MUST* cover any typed borrow derived from the sample payload. Rust binding note: stable-container typed receive uses a loan-backed stable receive method rather than an owned-frame helper.

=== Native-Frame Conformance Expectations

LoLa native-frame conformance tests *MUST* cover fixed sample-size rejection, alignment rejection, invalid native attributes, malformed frame-header and metadata-prefix rejection, payload/encoding mismatch rejection, hidden header/prefix/padding exclusion from payload views, exact standard and custom payload encoding preservation, stable-container metadata preservation, and stable-container typed borrowing only when the configured sample layout satisfies size, alignment, initialization, and lease-lifetime requirements.

Listener conformance tests *MUST* cover independent proxy subscriptions or an explicitly documented copying fanout path when multiple listeners match the same event. Environment-dependent native runtime smoke tests *SHOULD* distinguish stale or foreign samples from the test frame by validating frame magic before delivery.

[.specitem,oft-sid="dsn~up-transport-lola-native-frame-conformance~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
LoLa native-frame bindings *MUST* prove that invalid attributes are rejected, sample header bytes, metadata-prefix bytes, alignment padding, unused tail bytes, and exposed application payload bytes remain distinct, and that loan-backed typed stable-container borrowing is exposed only for valid LoLa sample leases that satisfy the raw sample safety contract.
--

== Routing And Configuration

The LoLa transport maps uProtocol source/sink filters to configured LoLa service instances and event names. Because LoLa deployment uses S-CORE communication configuration, the transport configuration MUST identify at least:

* local authority
* instance specifier
* service type
* event name
* sample size
* sample alignment
* maximum sample count
* middleware configuration path, when required by the runtime

Build integration for the S-CORE communication repository MAY use Bazel, but that integration SHOULD remain local to the LoLa transport implementation and MUST NOT impose Bazel as a workspace-wide requirement for language libraries or unrelated transports.

Native runtime smoke tests SHOULD report invalid frame magic explicitly. If stale or foreign samples can be present in the LoLa shared-memory segment, test code MAY drain those samples before sending the test frame, but runtime correctness is only proven once a sent frame with the expected uProtocol frame magic is received.
