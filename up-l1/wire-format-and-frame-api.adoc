== Goal

The Transport Layer frame API is serialization-neutral. A frame carries native uProtocol routing metadata, wire-format metadata, and payload bytes. The frame API MUST NOT require a format-specific generated message envelope.

== Native Frame Metadata

`UAttributes` is the native metadata carried by a frame. It contains the uProtocol metadata required for routing, validation, correlation, expiry, and prioritization.

Required fields:

* `id`: a uProtocol UUID.
* `source`: source `UUri`.
* `message_type`: publish, notification, request, or response.

Optional fields:

* `sink`: destination `UUri`.
* `priority`: priority class.
* `ttl`: message time-to-live in milliseconds.
* `request_id`: request UUID for response correlation.
* `traceparent`: distributed tracing context.

The metadata model is native to the language binding. It is not defined as a generated envelope requirement.

== Wire Encoding

`UEncoding` identifies the payload wire representation.

----
UEncoding {
  format_id: String,
  content_type: String,
  schema_ref: Optional<String>
}
----

`format_id` is a stable identifier for the codec family or IDL binding. `content_type` is the media type used by transport bindings, gateways, diagnostics, and tools. `schema_ref` can identify a schema URI, registry key, type hash, package-qualified type name, or another stable schema identity.

Adding a new payload format MUST NOT require changing the transport API.

== Frame Header

----
UFrameHeader {
  attributes: UAttributes,
  encoding: UEncoding
}
----

`UFrameHeader` combines native uProtocol metadata with explicit wire-format metadata.

`UFrameHeader` is a language-binding frame metadata bundle. It is not a new generated transport envelope and it is not intended to replace `UAttributes` as the protocol metadata model. Language bindings MAY choose a less ambiguous name, such as `UFrameMetadata`, if that better communicates the distinction between protocol metadata and transport frame bookkeeping.

Transport implementations MUST preserve both members when crossing a transport boundary. They MAY project individual `UAttributes` fields into transport-native metadata channels when doing so is cheaper than serializing the whole structure. They MAY also project `UEncoding` into transport-native metadata when the transport provides a suitable channel.

If a binding provides typed deserialization helpers on an owned frame or a zero-copy receive lease, those helpers MUST verify that the frame's `UEncoding` matches the selected `WireFormat` before decoding payload bytes. A mismatch MUST fail rather than silently handing bytes to the wrong deserializer.

== Native Message Builder

Language bindings SHOULD provide builder ergonomics for common frame construction without requiring applications to manually populate every metadata field.

A native builder:

* MUST build the language binding's native frame type, for example `UOwnedFrame`, rather than a generated transport envelope;
* MUST support Publish, Notification, Request, and Response frames;
* SHOULD support creating a Response from a Request's `UAttributes`;
* SHOULD support raw payload bytes;
* SHOULD support explicit `UEncoding` metadata;
* SHOULD support the same serializer contract used by owned and zero-copy transports;
* MAY support optional payload codecs such as Protocol Buffers when the binding exposes those codecs behind explicit features.

Builder helpers MUST validate message-type-specific metadata constraints before producing a frame. For example, Request and Response frames require RPC priority classes, Request frames require a non-zero TTL, Response frames require a request identifier, and request-only authorization fields MUST NOT appear on Publish or Notification frames.

The presence of a native builder MUST NOT require transports to accept generated message envelopes. Transports still consume native frame metadata plus payload bytes.

== Owned Frame

----
UOwnedFrame {
  header: UFrameHeader,
  payload: Bytes
}
----

`UOwnedFrame` owns its payload bytes. This is the natural representation for network, brokered, file, or in-process transports that accept application-owned buffers.

== Transmit Loan

`UTxBuffer` represents mutable transmit storage reserved from a zero-copy transport.

----
UTxBuffer {
  header() -> UFrameHeader
  header_mut() -> UFrameHeader
  payload() -> BytesView
  payload_mut() -> MutableBytesView
}
----

Serializers write directly into `payload_mut()`. Sending the buffer commits the transport-owned storage.

== Receive Lease

`UZeroCopyRxFrame` represents a receive-side lease. Dropping the lease releases the underlying transport storage.

----
UZeroCopyRxFrame {
  header() -> UFrameHeader
  payload() -> BytesView
}
----

Decoded values MAY borrow from the receive lease. Such values MUST NOT outlive the lease.

== Serializer Contract

Language bindings SHOULD provide a serializer contract equivalent to:

----
WireFormat {
  name() -> String
  encoding() -> UEncoding
}

Serializer {
  encoded_len(value) -> Integer
  serialize_into(value, mutable_bytes) -> Integer
}

Deserializer {
  deserialize_from(bytes) -> Value
}
----

The same serializer MUST be usable with an owned buffer or with a zero-copy transmit loan.

== Acceptance Criteria

* The frame API does not expose a format-specific generated envelope.
* Applications can select any wire format by providing serializer and deserializer implementations.
* The same serializer can target an owned buffer or a zero-copy transmit loan.
* The deserializer can return values borrowing from a receive lease where the language supports that lifetime model.
* Raw bytes are supported without an application schema.
* Typed deserialization rejects wire-format metadata mismatches.
* Common frame builder helpers produce native frames, not generated envelopes.
