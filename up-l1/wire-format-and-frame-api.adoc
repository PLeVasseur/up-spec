== Goal

The Transport Layer frame API is serialization-neutral. A frame carries binding-native uProtocol routing metadata, optional payload wire-format metadata, and optional payload bytes. The frame API MUST NOT require a format-specific generated message envelope.

== Native Frame Metadata

`UAttributes` is the native metadata carried by a frame. It contains the uProtocol metadata required for routing, validation, correlation, expiry, and prioritization.

Required fields:

* `id`: a uProtocol UUID.
* `source`: source `UUri`.
* `message_type`: publish, notification, request, or response.

Optional fields:

* `sink`: destination `UUri`.
* `priority`: priority class.
* `ttl`: message time-to-live in milliseconds.
* `request_id`: request UUID for response correlation.
* `traceparent`: distributed tracing context.
* `token`: access token.
* `permission_level`: authorization permission level.
* `commstatus`: communication status code.

The metadata model is native to the language binding. It is the binding representation of the protocol-level `UMessage` metadata used by the abstract Transport Layer API. It is not defined as a generated envelope requirement.

[.specitem,oft-sid="dsn~up-l1-native-frame-metadata-fields~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
Language bindings that expose frame metadata *MUST* preserve all required and optional `UAttributes` fields listed above when crossing a transport boundary, unless the existing transport mapping explicitly defines a lossy projection for that field.
--

== Wire Encoding

`PayloadEncoding` identifies the payload wire representation. It is present only when a frame carries a payload.

----
PayloadEncoding =
  StandardPayloadEncoding | CustomPayloadEncoding

StandardPayloadEncoding {
  payload_format: UPayloadFormat
}

CustomPayloadEncoding {
  id: String,
  content_type: String
}
----

Standard payload encodings use the upstream `UPayloadFormat` values from `UAttributes.payload_format` and are representable in generated `UMessage` envelopes. Custom payload encodings identify native-only byte-compatible layouts and are not representable in generated `UMessage` envelopes. A binding that intentionally serializes an entire native frame as a generated `UMessage` envelope *MUST* reject custom payload encodings rather than silently mapping them to `UPAYLOAD_FORMAT_UNSPECIFIED`. A custom `id` is a stable identifier for the native codec family or layout; `content_type` is the media type used by transport bindings, gateways, diagnostics, and tools.

`payload_format` values for standard encodings *MUST* be preserved exactly across native transport boundaries. Custom `id` and `content_type` values *MUST* be non-empty and *MUST* be preserved exactly across native transport boundaries.

Typed deserialization compatibility is defined as follows:

* A standard decoder matches only a standard frame encoding with the same `UPayloadFormat` value.
* A custom decoder matches only a custom frame encoding with the same `id` and `content_type` values.
* A standard decoder *MUST NOT* accept a custom frame encoding, and a custom decoder *MUST NOT* accept a standard frame encoding.

Adding a new native-only payload format MUST NOT require changing the transport API.

[.specitem,oft-sid="dsn~up-l1-frame-payload-encoding-presence~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
Frames without payload *MUST NOT* carry payload encoding metadata. Frames with payload bytes *MUST* carry payload encoding metadata, unless a language binding explicitly documents a raw-bytes default for that API. A present empty payload is distinct from no payload and carries payload encoding metadata. A receiver that observes payload bytes without encoding metadata and has no such documented raw default *MUST* reject the frame as invalid.
--

== Frame Metadata

----
UFrameMetadata {
  attributes: UAttributes,
  encoding: Optional<PayloadEncoding>
}
----

`UFrameMetadata` combines native uProtocol metadata with optional payload wire-format metadata.

`UFrameMetadata` is a language-binding frame metadata bundle. It is not a new generated transport envelope and it is not intended to replace `UAttributes` as the protocol metadata model.

Transport implementations MUST preserve both members when crossing a transport boundary. They MAY project individual `UAttributes` fields into transport-native metadata channels when doing so is cheaper than serializing the whole structure. They MAY also project `PayloadEncoding` into transport-native metadata when the transport provides a suitable channel. When `encoding` is absent, the frame has no payload encoding.

Language bindings SHOULD expose validators for native `UAttributes` and `UFrameMetadata`. Checked construction paths MUST validate message identifiers, URI roles, Request TTL, RPC priority, Response request IDs, and message-type-specific fields. Bindings MAY expose unchecked convenience constructors for low-level adapters and tests, but those constructors MUST be documented as unchecked and paired with checked alternatives.

If a binding provides typed deserialization helpers on an owned frame or a zero-copy receive lease, those helpers MUST verify that the frame's `PayloadEncoding` is compatible with the selected payload format before decoding payload bytes. A mismatch MUST fail rather than silently handing bytes to the wrong deserializer.

Rust binding note: the concrete frame API currently consists of `UAttributes`, `PayloadEncoding`, `UFrameMetadata`, `UOwnedFrame`, `UFrameBuilder`, `UTxLoanSpec`, `UTxBuffer`, and `UZeroCopyRxFrame`. These are binding-level frame APIs and are not generated protocol envelopes.

== Native Message Builder

Language bindings SHOULD provide builder ergonomics for common frame construction without requiring applications to manually populate every metadata field.

A native builder:

* MUST build the language binding's native frame type rather than a generated transport envelope;
* MUST support Publish, Notification, Request, and Response frames;
* SHOULD support creating a Response from a Request's `UAttributes`;
* SHOULD support raw payload bytes;
* SHOULD support explicit `PayloadEncoding` metadata;
* SHOULD support the same serializer contract used by owned and zero-copy transports;
* MAY support optional payload codecs such as Protocol Buffers when the binding exposes those codecs behind explicit features.

Builder helpers MUST validate message-type-specific metadata constraints before producing a frame. For example, Request and Response frames require RPC priority classes, Request frames require a non-zero TTL, Response frames require a request identifier, and request-only authorization fields MUST NOT appear on Publish or Notification frames.

A response-from-request helper MUST preserve the request identifier, source/sink reversal, request priority, and request TTL unless the application explicitly overrides those values. This keeps binding-level native frame APIs aligned with the existing RPC response semantics described by protocol transport mappings.

The presence of a native builder MUST NOT require transports to accept generated message envelopes. Transports still consume native frame metadata plus payload bytes.

== Service DTO Payloads

Native frames do not remove service-defined payload wire formats. If a service API, such as uSubscription, specifies Protocol Buffers DTOs, the binding MUST carry those DTOs as protobuf payload bytes inside the native frame when that service API is used. The generated DTO is the application payload representation, not the transport envelope.

== Owned Frame

----
OwnedFrame {
  metadata: UFrameMetadata,
  payload: Optional<Bytes>
}
----

An owned frame owns its payload bytes when payload is present. This is the natural representation for network, brokered, file, or in-process transports that accept application-owned buffers.

== Transmit Loan

A transmit loan represents mutable transmit storage reserved from a zero-copy transport.

----
TransmitLoan {
  metadata() -> UFrameMetadata
  payload() -> BytesView
  payload_mut() -> MutableBytesView
}
----

Serializers write directly into `payload_mut()` when a payload is present. Sending the buffer commits the transport-owned storage.

After `send_zero_copy` succeeds or fails, applications MUST treat the transmit loan as consumed unless the language binding explicitly documents recoverable ownership on failure.

== Receive Lease

A zero-copy receive frame represents a receive-side lease. Dropping the lease releases the underlying transport storage.

----
ReceiveLease {
  metadata() -> UFrameMetadata
  payload_len() -> Integer
  payload_reader() -> OrderedByteReader
  payload_slices() -> OrderedByteSliceIterator
  try_contiguous_payload() -> Optional<BytesView>
}
----

The payload may be backed by one contiguous region or by multiple ordered byte slices, depending on the transport. `payload_reader()` is the natural decode path for segmented-capable transports. `payload_slices()` exposes ordered payload slices without requiring a coalescing copy. `try_contiguous_payload()` returns a borrowed byte view only when the payload is available as one contiguous region.

Language bindings MAY expose a separate contiguous receive capability with an explicit method such as `contiguous_payload()` for transports that guarantee contiguity. Copy helpers such as `try_payload_to_vec()` MUST be named and exposed as checked opt-in copying helpers, not as the primary zero-copy receive path.

Decoded values MAY borrow from the receive lease when the selected deserializer can operate on the exposed payload shape. Such values MUST NOT outlive the lease. Borrowed deserializers that require `BytesView` contiguity MUST fail rather than silently copying segmented transport storage.

[.specitem,oft-sid="dsn~up-l1-zero-copy-receive-segmented-payload~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
Zero-copy receive leases *MUST* expose the payload byte order exactly as sent. If the underlying transport stores the payload in multiple regions, the receive lease *MUST* provide a segmented view or explicitly document that the advertised API is an owned/copying receive path rather than a zero-copy receive path.
--

== Serializer Contract

Language bindings SHOULD provide a serializer contract equivalent to:

----
PayloadFormat {
  name() -> String
  encoding() -> PayloadEncoding
}

Serializer {
  encoded_len(value) -> Integer
  serialize_into(value, mutable_bytes) -> Integer
}

Deserializer {
  deserialize_from(bytes) -> Value
}
----

The same serializer MUST be usable with an owned buffer or with a zero-copy transmit loan.

Serializers MUST NOT write partial payloads silently. If the supplied output buffer is too small, serialization MUST fail. If a serializer reports an encoded length and then writes a different number of bytes, language bindings SHOULD treat that as an invalid payload error.

== Stable-Container Payloads

Stable-container payloads are native custom payload encodings for typed values whose bytes can be transported and borrowed without a generated message envelope. They are intended for shared-memory and other loan-backed transports that can preserve payload alignment and lifetime.

The stable-container encoding is a `CustomPayloadEncoding` with:

----
id = "up.stable-container"
content_type = "application/vnd.uprotocol.stable-container;type=<stable-type>;variant=<variant>;size=<bytes>;align=<bytes>"
----

The `type` parameter is the cross-process and cross-language stable type identity. The `variant` parameter identifies the stable-container layout family. The `size` parameter is the exact payload byte length for fixed-size variants. The `align` parameter is the required minimum byte alignment of the first exposed payload byte.

The `fixed` variant represents exactly one fixed-size typed value. A receiver that borrows a `fixed` stable-container payload as a typed value *MUST* do so through a loan-backed stable-specific receive method such as `borrow_stable_payload<T>()` and *MUST* verify all of the following before constructing the typed borrow:

* `PayloadEncoding` is present and is a custom encoding with `id` equal to `up.stable-container`.
* `content_type` has media type `application/vnd.uprotocol.stable-container`.
* `type` matches the selected stable payload type identity.
* `variant` is `fixed`.
* Payload length is exactly `size` bytes.
* The exposed payload start address satisfies `align` and the selected stable type's alignment requirement.
* The receive lease keeps the payload storage alive for the entire typed borrow lifetime.
* The payload storage provenance is loan-backed or otherwise explicitly documented as stable for borrowing; owned buffers that may move or be reallocated MUST NOT be advertised as loan-backed stable-container borrows.

If a binding exposes payload loan provenance, the provenance value is diagnostic. Typed stable-container borrowing MUST depend on the loan-backed receive trait or equivalent lifetime/provenance proof, not on matching a particular public provenance enum value. Public provenance values SHOULD stay semantic, for example opaque transport loan or shared-memory loan, and SHOULD NOT become backend-specific or test-stub-specific taxonomy.

[.specitem,oft-sid="dsn~up-l1-stable-container-loan-backed-borrow~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
Language bindings that expose fixed-size stable-container typed borrowing *MUST* expose the safe typed borrow only through a loan-backed receive API. Owned native-frame transports *MAY* preserve stable-container bytes and metadata, but they *MUST NOT* advertise those owned bytes as loan-backed typed stable-container borrows.
--

Dynamic stable-container variants are reserved for future specification. A binding or transport that introduces a dynamic variant MUST define the variant metadata, length calculation, alignment rules, initialization requirements, and borrow lifetime rules before advertising typed dynamic borrowing.

[.specitem,oft-sid="dsn~up-l1-stable-container-encoding~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
Transport implementations *MUST* preserve stable-container custom encoding metadata exactly across transport boundaries. A transport that cannot preserve custom payload encodings *MUST* reject stable-container frames rather than silently degrading them to an unspecified or raw payload format.
--

[.specitem,oft-sid="dsn~up-l1-stable-container-layout~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
Stable-container transmit paths *MUST* reserve enough storage for the exact encoded payload length and requested alignment. Any hidden metadata prefix or padding inserted by the transport *MUST NOT* be exposed as payload bytes. Padding bytes outside the exposed payload are transport-private; bytes inside the exposed stable-container payload *MUST* be initialized according to the selected stable type's object representation contract.
--

Language bindings MAY expose an expert escape hatch for manually proving that a type is stable-container safe. Such an escape hatch *MUST* be unsafe or equivalently marked as expert-only in that language, and its documentation *MUST* require a proof of stable layout, exact size, alignment, initialized bytes including padding, valid bit patterns, no incompatible drop behavior, and receive-side provenance/lifetime safety. Binding-provided derive/code-generation paths SHOULD be the default application path.

.Stable-container transport conformance
[cols="1,3",options="header"]
|===
| Transport class | Stable-container expectation

| Owned network or broker transports, such as MQTT5
| Preserve payload bytes and `PayloadEncoding` metadata. They do not provide loan-backed typed borrowing and MUST NOT claim stable-container zero-copy receives.

| C++/FFI owned transports, such as vSomeIP bindings
| Preserve payload bytes and `PayloadEncoding` metadata across the binding-defined native frame prefix. They may copy through C++ payload storage and MUST document pointer and ownership contracts; they do not provide loan-backed stable-container typed borrowing unless a separate proven loaned path exists.

| Zenoh owned/`ZBytes` transports
| Preserve payload bytes and custom encoding metadata. A zero-copy receive path SHOULD expose ordered `ZBytes` slices without coalescing; typed stable-container borrowing is valid only when the binding can prove contiguity, alignment, lifetime, and loan-backed provenance for the exposed slice.

| iceoryx2 shared-memory transports
| Preserve metadata in user headers or hidden prefixes, reserve aligned shared-memory payload ranges, and expose receive leases whose lifetime backs typed stable-container borrows.

| LoLa shared-memory transports
| Preserve metadata in the configured sample layout, reserve aligned payload ranges within fixed-size samples, and expose receive leases whose lifetime backs typed stable-container borrows.
|===

== Acceptance Criteria

* The frame API does not expose a format-specific generated envelope.
* Applications can select any payload format by providing serializer and deserializer implementations.
* The same serializer can target an owned buffer or a zero-copy transmit loan.
* The deserializer can return values borrowing from a receive lease where the language supports that lifetime model.
* Raw bytes are supported without an application schema.
* Typed deserialization rejects incompatible wire-format metadata.
* `PayloadEncoding` is preserved across transport boundaries, including both standard `UPayloadFormat` values and native-only custom encodings.
* Common frame builder helpers produce native frames, not generated envelopes.
* Stable-container typed receive is loan-backed only and uses a stable-specific borrow method such as `borrow_stable_payload<T>()`.
