= The owned-frame SDK contract
:toc: preamble

The key words "*MUST*", "*MUST NOT*", "*REQUIRED*", "*SHALL*", "*SHALL NOT*", "*SHOULD*", "*SHOULD NOT*", "*RECOMMENDED*", "*MAY*", and "*OPTIONAL*" in this document are to be interpreted as described in https://www.rfc-editor.org/info/bcp14[IETF BCP14 (RFC2119 & RFC8174)]

This area holds the ordinary obligations of an SDK that offers owned-frame routes, and of the parts that work with it, that no protocol chapter and no item of the safety area states.

[[req-sdk-owned-frame-one-owner]]
== Frame storage and decoded values have one owner at a time

[.specitem,oft-sid="req~sdk-owned-frame-one-owner~1",oft-title="Frame storage and decoded values have one owner at a time",oft-needs="impl,utest",oft-tags="OwnedFrameSdk"]
--
*The rule.*
On each owned-frame route that it offers, an SDK whose core is not the element *MUST* give the storage that carries a frame, and each value decoded from a frame, one owner at a time: from the moment that the storage is lent or reserved, or the value decoded, until that owner gives it back or ends it.
While an owner holds such storage or such a value, a forgotten owner included, the SDK *MUST NOT* let another owner reach it, reuse it or end it.

*Where the core is the element.*
For the element and its bindings, the items that keep this rule are xref:../../safety/up-l1/native-wire.adoc#req-ssr-native-in-place[A native payload is written and read where it is carried, or its route is refused], xref:../../safety/up-l1/bindings.adoc#req-ssr-binding-lent-storage[Lent storage is exclusive, disjoint and stable for as long as it is held], xref:../../safety/up-l1/payload-paths.adoc#req-ssr-payload-written-once[A payload is written once, into the storage that carries it], xref:../../safety/seooc-up-rust/release.adoc#req-ssr-release-lease-drop[A lease gives back its slot and nothing else] and xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-slot-types[A decoded value is destroyed once, as its route's class admits].
--

[horizontal]
ID:: `+req~sdk-owned-frame-one-owner~1+`
Allocated to:: an SDK whose core is not the element, for each owned-frame route that it offers
Verification:: test, review
* *test*
** On each kind of owned-frame route that the SDK offers: a lent loan, storage reserved at setup and a decoded value, each held by one owner from its start until it is given back or ended, and none reachable through a second owner meanwhile.
** An owner that is forgotten: what it held neither reused nor ended, and reachable by no other owner.
* *review*: each path of the SDK that creates, passes or ends an owner of frame storage or of a decoded value.

*Rationale.*
The routes of this area are named for this rule.
One owner at a time is what lets a payload be written once into the storage that carries it, read in place, and ended exactly once.
Storage that two owners could reach could be written while it is read, or reused while it is held.
A forgotten owner still holds what it owned, so nothing that it held can be reused behind it.
For the element, the safety area states the rule for each part that keeps it, so this item binds only an SDK whose core is another.

[[req-sdk-owned-frame-adapter]]
== An adapter keeps a message whole across a crossing, or refuses it by name

[.specitem,oft-sid="req~sdk-owned-frame-adapter~1",oft-title="An adapter keeps a message whole across a crossing, or refuses it by name",oft-needs="impl,utest,uman",oft-tags="OwnedFrameSdk"]
--
*An adapter, a crossing.*
An adapter is a part that carries a message between a classic API and an owned-frame route.
A crossing is one such carriage, in one direction.

*What it states.*
An adapter *MUST* state, in the documentation that is released with it, each crossing that it supports: its direction, the routes and messages that it accepts, each copy and each allocation that it makes, and who owns each value afterwards.

*Exact.*
In each crossing that it supports, an adapter *MUST* keep all five of these properties:

* _Identity._
The value of each attribute of the message, whether a payload is present, and a present payload's bytes and encoding identifier arrive as they were given.
No attribute value is changed, defaulted or dropped, and the payload is neither decoded, re-encoded, converted nor truncated.
* _Ownership._
Each value has one owner at a time.
On success, what the adapter took passes to the new owner that the adapter states for the crossing, or the adapter ends it exactly once.
* _Lifetime._
Nothing that one side receives refers to storage of the other side beyond its owner's hold.
* _Allocation._
The crossing makes only the copies and allocations that the adapter states.
It changes neither the form, the heap class nor a guarantee of the owned-frame route (xref:../../safety/up-l1/payload-paths.adoc#req-ssr-payload-route-form[A route's form is fixed at setup, by what the route declares and never by a name]; xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-declared[The heap class is declared, with no default]).
* _Errors._
The caller gets, for each outcome, a result that states that outcome.
A refusal stays a refusal with its cause, and a loss or a partial delivery is not reported as delivery (xref:../../safety/seooc-up-rust/errors.adoc#req-ssr-error-no-silent-loss[No silent loss, and each loss counted once]).

*Or refused.*
An adapter *MUST* refuse each of these crossings, with a result that names the adapter's refusal and its reason:

* a crossing that it does not support;
* a crossing to or from a native route;
* a crossing that would need a payload decoded, re-encoded or converted;
* a crossing that it cannot make while keeping all five properties.

The adapter *MUST* leave a message whose crossing it refuses owned by the side that gave it.
The adapter *MUST NOT* complete a crossing in a weaker form.

*Local handles.*
A loan, a lease, a retained frame or another handle that owns or borrows storage of an owned-frame route is a local ownership interface.
An adapter *MUST NOT* pass one to a classic API as a message or inside one.
An adapter *MUST NOT* build a classic message that borrows such storage.
A crossing from a frame of an owned-frame route to a classic message is a stated copy into storage that the classic message owns, or it is refused.

*Waiting.*
Which operations an adapter may offer as a nonblocking attempt or as a progress step: xref:application.adoc#req-sdk-owned-frame-operation-kinds[Each message operation is a nonblocking attempt, a bounded wait or asynchronous, and none hides a wait].
--

[horizontal]
ID:: `+req~sdk-owned-frame-adapter~1+`
Allocated to:: each adapter
Verification:: test, compile-fail, review
* *test*
** Identity: for each crossing that the adapter states, in each direction, the value of each attribute, the payload bytes, the encoding identifier and whether a payload is present arrive as given, a present empty payload and an absent payload included.
** Ownership: each value owned by one owner at a time; on success, each value that the adapter takes passed to the new owner that it states for the crossing or ended once, counted by a test double.
** Lifetime: nothing that one side receives refers to the other side's storage once its owner's hold ends.
** Allocation: the copies and allocations of each crossing, counted, against those that the adapter states, with the route's form, heap class and guarantees unchanged.
** Errors: a refusal, a loss and a partial delivery on one side, each reaching the caller as that outcome, with its cause.
** A crossing that the adapter does not support, a crossing to and one from a native route, crossings that would need the payload decoded, re-encoded or converted, and one that the adapter cannot make while keeping all five properties: each refused with a result that names the adapter's refusal and its reason, the message still owned by the side that gave it, and no crossing completed in a weaker form.
* *compile-fail*: a loan, a lease and a retained frame, each where a classic message is required.
* *review*
** The documentation released with the adapter, against each crossing that it supports.
** Each path from a frame of an owned-frame route to a classic message: a stated copy into storage that the classic message owns, or a refusal, and no classic message that borrows storage of an owned-frame route.

*Rationale.*
An application that moves a message between a classic API and an owned-frame route needs the same message on the other side, owned once, and valid for as long as it is held.
A classic message and a frame of an owned-frame route carry the attributes in different forms, so what has to arrive unchanged is each attribute's value.
A crossing that changed an attribute, re-encoded a payload or reported a loss as a delivery would make the two APIs disagree about one message, unseen by either side.
A classic message carries no agreement on a native layout, so a native payload in one could be read where no such agreement holds (xref:../../safety/up-l1/native-wire.adoc#req-ssr-native-agreement[A native type is read only under its exactly agreed layout]).
A loan or a lease owns storage of a route only while its holder keeps it, and a classic message owns what it holds.
So a handle inside a classic message would outlive the storage that it refers to.
A refusal by name tells the application which crossing to change, where a weaker crossing would hide the difference.
